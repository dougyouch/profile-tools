```bash

bundle install

# Run all tests
bundle exec rspec

bundle exec rspec spec/profile_tools/collector_spec.rb

bundle exec rspec spec/profile_tools/collector_spec.rb:42

bundle exec rubocop
```

## Architecture

A Ruby gem (`profile-tools`) that wraps chosen methods, set from a YAML file, and logs per request how often each was called, how long it took, how many objects it allocated and how much garbage collection ran inside it. See ARCHITECTURE.md for details.

- **ProfileTools** (`lib/profile-tools.rb`) - Module with the public API (`load`, `profile`, `profile_method`, `stop_profiling`, `instrument`) and the frozen list of profiled methods.
- **MethodName** - Parses `"Class#method"` / `"Class.method"`.
- **MethodWrapper** - Prepends a `WrapperModule` with `def name(...) = instrument { super(...) }` wrappers.
- **Profiler** - Per-thread run; publishes the `profile.profile_tools` notification when the outermost call ends.
- **Collector** / **MethodStats** - Measure calls and hold the per-method totals for one run.
- **LogSubscriber**, **Middleware**, **Railtie** - Logging, one run per Rack request, and zero-code Rails setup from `config/profile_tools.yml`.

### Key constraint: nothing may allocate inside a measurement

Allocation counts are exact only because the wrapper and collector allocate nothing between the before and after `GC.stat` readings. When changing `MethodWrapper`, `Profiler#instrument` or `Collector#instrument`, keep the hot path allocation-free (`...` forwarding, anonymous `&` block forwarding, `"literal".freeze`, no new objects) and keep the exact-count specs in `spec/profile_tools/method_wrapper_spec.rb` and `spec/profile_tools/collector_spec.rb` passing. `...` forwarding only stopped allocating in Ruby 3.4, which is why that's the minimum.

## CI

`.github/workflows/ci.yml` runs RuboCop, the YARD docs check, and the specs with `Gemfile.lock` and the 100% line/branch coverage gate on Ruby 3.4 (the gemspec minimum) and on the `.ruby-version` Ruby. On pushes to `master`, it publishes `coverage.svg` (line) and `branches.svg` (branch) from `script/coverage_badge.rb` to the orphan `badges` branch for the README badges.

## Releases

Releases are automated by release-please (`.github/workflows/release.yml`). Conventional commits on `master` (`fix:` → patch, `feat:` → minor, `!`/`BREAKING CHANGE` → major, or minor while below 1.0) update an open release PR that bumps `lib/profile_tools/version.rb` (`ProfileTools::VERSION`, read by the gemspec) and `CHANGELOG.md`. Merging that PR tags `vX.Y.Z`, creates the GitHub release, and publishes the gem to RubyGems. Don't bump the version by hand.

## Code Commits

Format using angular formatting:
```
<type>(<scope>): <short summary>
```
- **type**: build|ci|docs|feat|fix|perf|refactor|test
- **scope**: The feature or component of the service we're working on
- **summary**: Summary in present tense. Not capitalized. No period at the end.

## Documentation Maintenance

When modifying the codebase, keep documentation in sync:
- **ARCHITECTURE.md** - Update when adding/removing classes, changing component relationships, or altering data flow patterns
- **README.md** - Update when adding new features, changing public APIs, or modifying usage examples
- **UPGRADING.md** - Update when making a breaking change
- **YARD comments** - Every public class, module, constant and method needs one; mark internals with `@api private`
- **CHANGELOG.md** - Generated by release-please from commit messages; don't edit by hand except to fix release notes
